# Cursor Ask用：Terminal Robotの次工程に関する意見確認

以下のファイルを読み取り専用で確認してください。コードや文書は変更しないでください。

- `@src/mirocore/terminal_robot/__main__.py`
- `@src/mirocore/terminal_robot/state.py`
- `@src/mirocore/terminal_robot/expressive.py`
- `@src/mirocore/terminal_robot/reply.py`
- `@tests/terminal_robot/test_main.py`
- `@tests/terminal_robot/test_expressive.py`
- `@docs/terminal-robot-state-design.md`

## 確認したいこと

現在、私は次のように考えています。

> `test_expressive.py`は、現在存在する`RobotState`ごとの表示を確認できているため、表示部分はいったん完了とする。新しい表示仕様を追加しない限り、表示テストを増やし続ける必要はない。次はTerminal Robot全体の整合性を高めるため、`handle_empty_input()`の契約と状態遷移テストを小さな一単位として整理する。その確認が完了してから、`reply.py`などの新規実装へ進む。

この判断が、現在のコード、テスト、設計文書から見て妥当か、あなたの意見を聞かせてください。

## 調査してほしい観点

1. `test_expressive.py`は、現在の`add_prefix()`の仕様を十分に検証できているか。
2. `handle_empty_input()`の引数、戻り値型、実際の戻り値、呼び出し条件に矛盾がないか。
3. 空入力時の状態変更が、状態遷移を`transition()`へ集約する設計方針と一致しているか。
4. `test_main.py`の状態遷移テストは、`state.py`に定義された遷移を十分に検証できているか。
5. 新規実装へ進む前に修正すべき問題と、後回しにできる改善点は何か。
6. 空入力専用イベントを追加することが最小で自然な設計か、それとも現在のMVPには過剰か。

## 回答時の条件

- 実際の呼び出し経路を追って判断してください。
- コードから確認できた事実、推測、改善提案を区別してください。
- 表面的なスタイル指摘ではなく、動作、型の契約、責務、テスト範囲を優先してください。
- 問題点を無制限に列挙せず、新規実装の判断に影響するものを最大3件に絞ってください。
- 大規模なリファクタリングや、LLM、DB、非同期処理など将来機能の提案は不要です。
- 完成コードやパッチは提示しないでください。
- 判断に必要な情報が不足している場合だけ、質問を最大3件まで提示してください。

## 希望する回答形式

1. 結論：現在の判断に賛成、条件付きで賛成、反対のいずれか
2. コードから確認できた事実
3. 優先度の高い問題（最大3件）
4. 次に行う最小の作業単位
5. その作業の完了条件と確認すべきテスト
6. 未検証事項

最後に、次のどちらを推奨するかを明記してください。

- `handle_empty_input()`と状態遷移テストを先に整理する
- 現状のまま`reply.py`などの新規実装へ進む

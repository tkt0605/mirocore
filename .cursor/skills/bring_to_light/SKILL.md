# 問題を洗い出す

会話で扱っている問題について、今の実装を読んでから現状をまとめる。ファイルは変更しない。修正案は求められたときだけ書く。

## 手順

1. 対象は会話中の問題に限る。リポジトリ全体は、そう求められたときだけ読む。
2. 実装、その呼び出し元、関連テスト、設計メモを読む。完了条件は、入口から失敗が表面化する箇所まで呼び出し順を追えること。
3. コード確認、実行確認、推測、未検証を分けて書く。
4. 下の形で出力する。完了条件は、最初の2文で結論が分かり、未解消の各項目が「いま何が起きるか」を述べていること。

## 出力

日本語で書く。最初の2文で、解消したことと、まだ残ることを述べる。

```markdown
## もう解消していること

[いまの実装が防いでいることと、その仕組み。]

## まだ残っていること

**1. [観測できる振る舞い]**

[誰が誰を呼び、戻り値や例外がどこへ渡り、ファイルとプロセスがどうなるか。流れを見せるのに必要な箇所だけ引用する。]
```

未解消は、起きうる順に番号を振る。項目の見出しは、利用者から見える結果にする。本文には呼び出し順、戻り値、ファイルが残るか、プロセスがどこで終わるかを書く。テストの有無は、その項目の中に書く。

古い設計メモと今のコードが違うときは、今のコードを優先し、メモはメモとして扱う。

## 結論

ローカルの自動テストは 53 件すべて成功した。この成功が保証するのは、書かれているテストの範囲だけである。記憶の残り方と、検索が記憶をどう返すかに、今の設計の問題が集中している。

状態遷移 `IDLE → LISTENING → THINKING → SPEAKING → IDLE`、空入力の `EMPTY`、`/q` と `Ctrl+C` の終了、重複記憶を足さないこと、不正なキーで既存ファイルを壊さないことは、テストどおりに成立している。LLM も DB 接続も、いまの会話経路には入っていない。

長期記憶を残す前に直すのは、保存の途中失敗でファイルが空になること、名前が保存先パスになること、検索契約がテストされていないこと、入出力失敗がプロセスを終えることである。

## 各問題の根拠と対応の方向

### C01：保存途中の失敗で既存記憶が消える

- **箇所**：`src/mirocore/terminal_robot/write_read.py` の `write_user_local_json()`。既存ファイルを `"w"` で開いてから `json.dump()` している。
- **原因**：開いた時点で中身は空になる。書き込みの完了前にプロセスが止まると、ファイルは空か書きかけになる。
- **呼び出し**：この書き込みは `on_thinking` の検索、記憶追加、挨拶のすべてで走る。`Ctrl+C` はループの外側で拾うが、書き込み中に割り込まれると、終了メッセージのあとファイルだけが中途半端になり得る。
- **読み込み**：捕まえているのはファイルが無い場合の `FileNotFoundError` だけである。空ファイルや書きかけの JSON は `JSONDecodeError` になる。
- **影響**：`main` は `KeyboardInterrupt` しか捕捉しない。名前の読み込みでプロセスが終わり、プログラム側に復旧手順がない。
- **テスト**：`test_read_user_local_json_invalid_file` は、ファイルが無いときに `None` になることを見ている。壊れた JSON は見ていない。
- **対応の方向**：同じディレクトリの一時ファイルへ書き終えてから置き換える。壊れたファイルでも起動を続けられることをテストで固定する。

### C02：ユーザー名が保存先パスになる

- **箇所**：`local_memory_path()` と `inputer_user_name()`。保存先は `memory_index/<名前>/<名前>_memories.local.json` で、区切り文字の検査はない。
- **実行確認**：名前 `../../outside-repo` の解決先はリポジトリの外、`/Users/komadatakato/outside-repo_memories.local.json` だった。ファイルは作成していない。
- **再訪**：打った名前ではなく、ファイルの中の `name` を以後のパスに使う。
- **影響**：対話している本人が名前を打てるので、遠隔から入る経路ではない。名前の打ち間違いや、後から編集した `name` が `memory_index` の外への書き込みになる。README の「ファイルシステムへは許可した境界だけを通す」は、この経路にはまだ無い。
- **対応の方向**：使える名前を一つの関数で決める。解決したパスが保存ディレクトリの外なら拒否する。ファイル内の `name` と入力した名前が違うときは、その `name` をパスに使わない。

### C03：検索契約が片側だけで、テストが無い

実行した分類は次のとおり。

| 入力 | 判定 | 検索語 |
|---|---|---|
| `図書館を覚えてる` | 検索 | `図書館` |
| `図書館を覚えてる？` | 検索 | `図書館` |
| `覚えてる？ 図書館` | 検索にならない | なし。挨拶語も自分を指す語も無いので、聞き返しになる |
| `昨日話した予定って何だっけ？` | 検索にならない | なし |
| `はを覚えてる` | 検索 | `は` |

`は` を、助詞「は」を含む既存の 3 件に掛けると 3 件とも返った。一文字の部分一致が、保存済みの文を画面にまとめて出す。

検索を記憶追加より先に見る修正はコードに入っている。`僕の名前を覚えてる` は検索になり、その文は新規記憶にならない。この振る舞いを固定するテストは無い。53 件が成功しても、検索を壊しても気づけない。

引き継ぎ文書の「覚えてる？ 図書館」は、文書上も確定仕様ではない。今のコードの契約は「定型句で終わる文」である。

- **対応の方向**：受け付ける文の形を一つに決める。短すぎる検索語は検索しない。正常系、0 件、複数件、検索文を記憶しないこと、をテストに書く。

### C04：入出力の失敗がプロセスを終える

設計では、未定義の遷移は `ERROR` を経て `IDLE` に戻る。実際にそう扱っているのは `KeyError` だけである。`JSONDecodeError`、`OSError`、`ValueError` はループの外へ出る。

思考中の表示より前に保存しているので、保存に失敗したターンは「考え中」も出ない。

- **対応の方向**：失敗したら `ERROR` の表示を出して入力へ戻す。記憶ファイルは直前の完全な内容のままにする。C01 とセットで直す。

### C05：誤った文が記憶になり、消えない

`私立大学に行きたい` は、実行すると記憶候補そのものになった。`私` が文の一部に含まれるためである。保存するのは事実の抜き出しではなく、発言全文である。書き込みは追記だけで、同じ文を消したり直したりする操作はない。

この広さは、コード内でも狭い規則として書かれている。検索の契約を固定した次に、候補の条件を狭めるか、そのターンでは保存しない選択を置く。

### C06：不正遷移の回復を、テストが正解にしている

`THINKING` に `START_LISTENING` を渡すと、エラー文を出した直後に `IDLE` が返る。`ERROR` の表情はテストされているが、対話ループはこの状態に留まらない。

`test_terminal_robot_state` は、遷移表に無い `EMPTY` + `ERROR_SHOWN` の期待値を `IDLE` にしている。不正な組み合わせが、回復として合格している。遷移表の純粋さは保てている。呼び出し側が失敗を成功に見せているので、後から遷移を直したときに回帰が隠れる。

### C07：起動説明と実装が分かれている

`uv run python -m mirocore.terminal_robot` が会話本体である。記憶はカレントディレクトリの JSON である。

`docker compose up` のコンテナコマンドは `uv run mirocore` で、中身は `Hello from mirocore!` である。PostgreSQL は起動定義があるが、会話コードは接続しない。`src` はコンテナ内で読み取り専用である。コンテナの中で Terminal Robot を動かすと、記憶はコンテナのファイルシステム側に書かれ、コンテナを消すと残る保証がない。この起動は未検証である。

状態設計の文書は、空入力を `ERROR`、応答を `__main__.py` の固定文と書いている。実装は `EMPTY` と `reply.py` である。方針の文書を正としてコードを直すと、動いている遷移を戻すことになる。

### C08：ローカルではまだ表面化していないもの

- `options.py` が未使用の `tkinter` を import している。この環境のテスト収集は成功しているので、ローカルの Python には `tkinter` がある。`python:3.13-slim` では対話起動とテスト収集がここで止まる可能性がある。Docker では未検証。
- `numpy` は依存関係にあり、ソースからは使っていない。
- 空の名前は `inputer_user_name` が自分を呼び直す。空入力を重ねると再帰の上限で落ちる。
- ` /q` や `/q ` は終了コマンドの集合と一致せず、通常の発言として処理される。
- `tests/test_config.py` にテスト関数が無い。`DATABASE_URL` が無くても `uv run mirocore` は通る。接続 URL の表示はコメントアウトされたままである。
- Compose 内の DB パスワードは `miroc` で、ポートはホストに出ていない。会話経路は DB を使わない。

## 今回は優先度を上げなかったもの

LLM のサンドボックス、SQL、ハードウェア制御は、呼び出しが会話経路に入っていない。接続 URL を表示する処理はコメントアウトされたままである。状態遷移表そのもの、重複記憶を足さないこと、不正キーで既存ファイルを維持することは、テストが押さえていた。

これらを安全だと判定したわけではない。今回の結果は、ローカルの Terminal Robot 試作の範囲に限る。

## 手を付ける順

1. 記憶ファイルを置き換えで書き、壊れたファイルでも起動できることをテストする（C01、C04）。
2. 名前から保存パスを作る境界を一つに決め、外への書き込みを拒否する（C02）。
3. 検索として受ける文を一つに固定し、短い検索語、0 件、複数件、検索文を記憶しないことをテストする（C03）。
4. その後で、誤記憶の条件と `ERROR` の見え方を触る（C05、C06）。文書と Docker のずれ（C07、C08）は、その起動経路を使う前に合わせる。
